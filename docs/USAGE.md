# 使用指南（逐步）

本文面向最终用户。安装与从源码构建见 [README.md](../README.md)；开发者目录见 [DEVELOPMENT.md](./DEVELOPMENT.md)。

> **重要**：本扩展通过你已登录的浏览器会话访问 X 网页端内部接口，**可能违反 X 服务条款**，存在限流或账号风险。开发环境**未对真实 X 账号做过验证**。请自行评估后再使用，并建议加大页间延迟、避免频繁全量同步。

## 0. 一个扩展：X Toolkit

v0.7.0 起产品名是 **X Toolkit**（书签功能与打击账本在同一个 MV3 扩展里）。加载 `dist/` 之后，请停用单独的 X Strike Ledger，否则 x.com 会被注入两次。0.7.1 起，静音/屏蔽进入本地队列后再点 X 的菜单。0.7.2 起，可以把帖子里选中的词加入关键词包；命中只出黄标，不自动记一笔。0.7.3 起，可选的 BYOK 建议若判断为垃圾或营销，可以经确认把抽出的短词存进一个词库，这一下也不记一笔。0.7.4 起，已关注或白名单账号在时间线上显示保护徽章，已有标签显示成「垃圾×2」；点芯片只打开标记。0.7.5 起，已关注只挡住关键词/黄标的自动入队；你手动记满阈值后仍可静音或屏蔽。白名单仍然不会自动入队。0.7.6 起，常营销 / 常垃圾标在作者身上，书签库显示芯片，默认不记一笔、不静音、不屏蔽。0.7.7 起，推文详情页的回复可以单独扫描关键词：默认关闭；打开后默认折叠命中的那一条或只出黄标，不会因评论命中自动静音或屏蔽。0.7.8 起，黄标或 AI 建议可以点「不像」：本地停用命中的词，或按冷却天数降低敏感度，也可以记一条例外短语。不会撤销已确认的记一笔，也不会静音或屏蔽。0.7.9 起，折叠条默认写出原因（命中的词，或「AI 建议垃圾」）；多条收成 +N。点折叠条展开，再点收起。选项里可以关掉「折叠条显示原因」。0.7.10 起，可以导入或订阅一份可选社区名单：默认关闭；打开后命中只出黄标，或按折叠策略折叠。不记一笔，不静音，不屏蔽。

打击账本的静音/屏蔽默认关闭，且只通过 X 页面上的菜单按钮操作，不走书签同步用的 GraphQL。

在时间线上试队列：选项页 **打击账本** 打开「允许通过 X 的菜单执行静音/屏蔽」（建议模式保持「确认」，每日上限先设小）。打开 x.com 时间线，用「标记」→「排队静音」（已关注账号也可以），或在达到阈值的确认框里勾选静音/屏蔽。留在能看到该帖的时间线，扩展会逐条点 X 自己的「更多」菜单（间隔另加约 1–2.5 秒抖动）。同一页的 **队列与限流** 可看队列长度、失败项、最近错误和今日已用/上限，并可暂停、继续、重试或清空。白名单不会自动入队。已关注账号不会因关键词或黄标自动入队；你手动记满阈值后仍按自动/确认/仅提示处理。关注状态未知和「仅提示」不会自动入队。

### 从帖子加入关键词

1. 在 x.com 的某条帖子里选中一个词。
2. 点该帖的 **标记**，在面板里选关键词包，点 **加入此包**。也可以右键选中文字，选 **把选中文字加入关键词包**，再点具体词库。
3. 这只保存关键词。帖子上若出现黄标 **可疑**，次数不会增加；要记账仍需你确认标记。
4. 选项页 **打击账本 → 关键词包** 可启用/停用、编辑，并用 **词库文本** 导入或导出 `.txt`。可选「记录关键词命中」查看最近最多 40 条命中，便于调试规则。

### 从一条 AI 建议存成关键词

1. 选项页 **打击账本 → AI 建议** 打开 BYOK（默认关），填写你自己的端点和 key。Key 存在 `xslSecret`。
2. 在 x.com 对一条帖子点 **让 AI 看一看**。结果按帖子内容哈希缓存，不会把时间线整页发给模型。
3. 芯片若是垃圾或营销，点开它，选一个词库，再点 **存为关键词**。抽出的短词一次写入该包，只影响以后的黄标。
4. 要给账号记一笔，点旁边的 **确认记一笔**。保存关键词不会自动记。

### 保护徽章和标签芯片

1. 重新构建并加载 `dist/`（版本 0.7.5）。打开 x.com 时间线。
2. 你关注的账号，名字下方和「标记」那一行都会出现绿色 **已关注保护**（英文界面是 **Protected**）。只在白名单、且页面显示未关注时，中文是 **白名单保护**。已关注的悬停说明是：不会因关键词/黄标自动入队；你手动记满阈值后仍可静音或屏蔽。白名单的悬停说明仍是：不会自动入队。
3. 这个账号如果已经有打击次数，同一位置会出现 **垃圾×2** 这样的芯片，不用先打开标记。最多 4 个，其余收成 **+N**。
4. 点芯片打开标记面板。这一下不记一笔，也不入队。要记账仍要点面板里的标签。

### 书签里的常营销 / 常垃圾（0.7.6）

作者标记存在打击账本 `xsl` 里，不另建一份。书签不会被删，也不会因此静音或屏蔽。

1. 重新构建并加载 `dist/`（版本 0.7.6）。
2. 打开列表或书签页。某个作者在账本里的营销或垃圾次数达到书签芯片阈值（默认 3）时，帖子上会出现 **常营销** 或 **常垃圾**。
3. 在一条书签上点 **标为常营销**（或批量选中后点同一按钮）。这个作者已有的书签和以后同步进来的书签都会显示芯片。**取消常营销**只去掉你手动标的那一下；次数如果仍达阈值，芯片还在。
4. 搜索框输入 `author:marketing` 或 `strike:spam`。列表筛选里也可以选「作者标记」。
5. 设置页 **书签与打击账本**，或打击账本页 **书签库联动**：可以关掉「按打击次数显示芯片」、改芯片阈值，或打开「标作者时同时记一笔」。最后一项默认关闭。打开后每个作者最多记一笔，仍然不入队。
6. 时间线上打开 **标记**，勾选 **同时在书签库标出这个作者**，再点垃圾或营销。没记满次数也会在书签里显示。不勾选时，记满书签芯片阈值仍会显示。

### 评论区回复（0.7.7）

1. 重新构建并加载 `dist/`（版本 0.7.7）。选项页 **打击账本 → 评论区**。
2. 「扫描评论区回复」默认关闭。打开后，只在一条推文的详情页里扫描回复，不扫描主帖，也不代替时间线的关键词预标。
3. 回复正文命中现有关键词包时，出现黄色 **可疑**。默认把这一条回复折叠起来（可以点「显示这条」）。若选「只出黄标，等你确认」，则不折叠。
4. 点黄标再确认，才会记一笔。这一下不会自动静音或屏蔽。白名单的回复不折叠。你关注的账号不自动折叠。
5. 要静音或屏蔽，打开 **标记**，点 **排队静音** 或 **排队屏蔽**。仍由时间线去点 X 自己的菜单。

### 这条不像（0.7.8）

1. 重新构建并加载 `dist/`（版本 0.7.8）。
2. 帖子上的黄色 **可疑**，或 **AI 建议垃圾 / 营销**，点开后选 **不像**（英文 **Not spam**）。
3. 确认框列出将停用的词。点 **停用这些命中** 之后，这些词单独出现不再标黄。已经记过的次数还在。不会静音或屏蔽。
4. 可以勾选例外短语。默认只跳过这个作者；也可以改成任何作者。短语只存在这台浏览器。
5. 选项页 **打击账本 → 误判与冷却** 可以改冷却天数（0 表示一直停用，直到撤销），并撤销某一条。撤销不会改已确认的打击次数。

### 折叠条上的原因（0.7.9）

1. 重新构建并加载 `dist/`（版本 0.7.9）。选项页 **打击账本 → 评论区**，「折叠条显示原因」默认是开的。
2. 时间线上已经被本地折叠的帖子，条上会写出命中的词（例如 `词库 · 空投`）。好几条命中时只留最主要的一条，其余是 `+N`。没有词库命中、但有 AI 建议时，显示原来的 **AI 建议垃圾** 或 **AI 建议营销**。都没有时，显示已有的 `垃圾×3` 这类芯片。
3. 评论区扫描打开、并且设为折叠这条回复时，折叠条同样写出命中的词。白名单仍然不折叠。你关注的账号仍然不自动折叠。
4. 点折叠条看原文，再点一次收起。旁边的「展开这条 / 收起」是同一个开关。黄标仍然只在你确认后才记一笔。
5. 关掉「折叠条显示原因」后，帖子仍会折叠，只是条上不再写具体的词。这一项不改变记账次数、静音/屏蔽队列、白名单、已关注或误判记录。

这条展示**没有**在真实 X 账号上验证过。

### 可选社区名单（0.7.10）

社区名单只影响黄标和折叠。它不记 strike，不进入静音/屏蔽队列，点黄标也不记账。

1. 重新构建并加载 `dist/`（版本 0.7.10）。选项页 **打击账本 → 社区名单**。
2. 「启用社区名单」默认关闭。先导入或订阅，再勾选启用，并选择 **仅黄标** 或 **可折叠**，然后点 **保存**。只导入、不勾选，时间线上不会出现新的黄标。
3. 可折叠时：白名单不折叠，已关注不折叠，详情页正在看的主帖不折叠。其余时间线帖子和回复可以折叠。折叠条写成 `社区名单 · 名称`。点黄标只看到名单名称，可以点「不像」，没有记一笔。
4. 订阅 URL 可以手动刷新，也可以删除。失败时仍用上次缓存。名单留在这台浏览器里。

JSON 格式：

```json
{
  "format": "x-toolkit-community-list",
  "version": 1,
  "name": "示例名单",
  "handles": ["spam_bot"],
  "keywords": ["加群领资料"]
}
```

文本格式：`# name: 示例名单` 写标题，`@spam_bot` 是账号，其它一行一个词。匹配是原文包含，不是正则。

这条逻辑**没有**在真实 X 账号上验证过。

## 1. 安装扩展

任选其一：

### A. 加载已构建的 `dist/`（最快）

1. 若你拿到的是发布包（如 `bookmark-keeper.zip`），解压后应能看到其中的 `dist/` 目录（含 `manifest.json`、`background.js` 等）。
2. Chrome 打开 `chrome://extensions`，打开右上角 **开发者模式**。
3. 点击 **加载已解压的扩展程序**，选择 **`dist/`** 文件夹（不是仓库根目录）。
4. 固定扩展图标到工具栏，便于打开 popup / 侧边栏入口。

### B. 从源码构建后再加载

```bash
git clone <你的仓库 URL>
cd bookmark-keeper
npm install
npm run build          # 生成 dist/
```

然后按上面 A 的步骤加载 `dist/`。

源码仓通常**不提交** `dist/`；日常开发用 `npm run build` 或 `npm run dev`（watch）。

## 2. 首次使用：登录 → 抓凭证 → 同步

扩展**不**提供独立登录页，也不使用 X 官方付费 API。它依赖你在**同一 Chrome 配置**里已经登录 x.com。

### 步骤

1. **登录 X**  
   在 Chrome 打开 <https://x.com>，用你的账号正常登录，确认能浏览时间线。

2. **打开书签页以捕获凭证**  
   访问 <https://x.com/i/bookmarks>（或 twitter.com 对应书签页）并 **刷新一次**。  
   扩展的 Service Worker 会监听页面自己发出的 `/i/api/graphql/*` 请求，抓取 Bearer、csrf、client uuid、transaction-id 等，并学习 queryId。  
   **不要**把 cookie / token 粘贴到任何地方；也不要发给任何人。

3. **打开扩展 UI**  
   - 点击扩展图标 → popup；或  
   - 打开 **侧边栏（side panel）**；或  
   - 右键扩展 → **选项**，进入完整 options 页。

4. **到「同步」页开始同步**  
   - **增量同步**：适合日常；遇到本地已有且仍为 active 的书签后停止。  
   - **全量同步**：会翻完书签分页并（按设置）检测已取消书签；耗时更长、请求更多，确认后再执行。

5. **观察进度**  
   可暂停 / 继续 / 取消。若遇 429，会按限流 Reset 等待后继续。Service Worker 被 Chrome 回收时，同步可能标为暂停，之后点「继续」从断点恢复。

6. **全量同步报告**  
   全量同步成功结束后会弹出 **Full sync report**：展示本次抓取条数、上次全量同步时间、内容分布（视频 / 图片 / 文章 / 长帖 / 普通帖）以及收藏最多的作者 Top 5。也可随时在「同步」页点击 **同步报告** 打开。点某作者旁的「查看书签 →」会跳到书签列表并按 `from:handle` 过滤。

### 若提示鉴权失败 / 无凭证

- 确认已登录 x.com，并再次打开书签页刷新。  
- 确认加载的是本扩展的 `dist/`，且未禁用相关权限（storage、webRequest、declarativeNetRequest、x.com host）。  
- 换账号或清 cookie 后需重新打开书签页抓凭证。

## 3. 书签库：搜索与浏览

- 顶部搜索框支持关键词与语法（见下一节）。  
- 过滤面板（作者 / 日期 / 文件夹 / 媒体 / 标签 / 状态等）与语法取 **AND**。  
- 排序：相关性、收藏时间、发布时间、点赞、浏览量等。  
- 结果分页；命中词高亮。  
- 空查询时用 IndexedDB 索引分页，**不会**一次把全库载入内存。

状态说明：

| status | 含义 |
| --- | --- |
| `active` | 当前仍视为有效书签/记录 |
| `tweet_deleted` | 同步时发现推文已删除（tombstone 等） |
| `unbookmarked` | 全量同步成功后，本次未再见到的原 active 书签 |

本地默认**保留**这些记录，可用 `is:deleted` / `is:unbookmarked` 筛选。

## 3b. 列表页（Library，v0.4）

在选项页顶部切换到 **「列表」**（侧边栏同样有入口）：

- **主题**：默认 **深色**（X 风格近黑背景）；可在设置页或列表工具栏切换 **浅色/深色**（偏好写入 `chrome.storage.local` 的 `settings.theme`）。
- **表格**：列包括 #、用户、文件夹、帖子、媒体、浏览、转发、喜欢、回复、发布时间。
- **列**：右上「列」下拉可勾选显示/隐藏，并「重置布局」（偏好写入 `chrome.storage.local`）。
- **工具栏**：搜索框、筛选、导出、同步快捷按钮、主题切换（☀️/🌙 或 浅色/深色）。
- **筛选面板**：时间范围 + 快捷（近 7/30 天、近 1 年、全部）、最旧优先开关、文件夹 / 内容类型 / 帖子类型 / @用户 / 可用性；底部「搜索」「重置」。
- **导出面板**：帖子 | 媒体 页签；全部 vs 已选；CSV / JSON / Markdown / PDF（打印页）；自定义文件名；「开始导出」走现有 `export`/`batch`（量大自动分批 zip）。
- **分页**：默认每页 50（可选 20/100）；底栏显示选中数。数据经 Dexie/搜索分页加载，**不会**一次载入全库。
- **取消 X 端书签**：勾选后工具栏出现「取消 X 端书签」（与书签页同确认/可选删本地）；行末 🗑 可单条取消。

原有「书签」卡片搜索页、文件夹/标签/同步报告仍保留。

## 4. 搜索语法

词与词之间默认 **AND**。支持：

| 语法 | 示例 | 说明 |
| --- | --- | --- |
| 关键词 | `rust async` | 全文（MiniSearch + 中文分词） |
| 短语 | `"精确短语"` | 引号内整段匹配 |
| 排除 | `-广告` | 排除含该词的结果 |
| 作者 | `from:alice` | screen_name |
| 日期 | `since:2024-01-01` `until:2024-06-30` | 也支持 `YYYY-MM` / `YYYY` |
| 文件夹 | `folder:"My Folder"` `folder:none` | 无文件夹用 `none` |
| 媒体/链接 | `has:image` `has:video` `has:link` `has:quote` `has:media` | |
| 标签 | `tag:todo` | |
| 状态 | `is:active` `is:deleted` `is:unbookmarked` | |
| 来源 | `source:bookmark` `source:timeline` | 书签 vs 发帖同步 |

发帖同步写入的文件夹形如 `timeline:@handle`，可用 `folder:timeline:@someone` 过滤。

## 5. 发帖同步（UserTweets）

在 **同步** 页的「公开发帖」面板：

1. **按账号**：输入 `@handle` 或主页链接 `https://x.com/xxx`，点「同步此账号」。  
2. **我的发帖**：点「同步我的发帖」——扩展尝试解析当前登录账号的 screen_name，再拉 UserTweets。

特点：

- 数据 `source: timeline`，放入文件夹 `timeline:@handle`，与书签分区。  
- 若同一 `tweet_id` 已是书签，不会降级覆盖为仅时间线。  
- **连续翻页极易触发限流**；请把设置里页间延迟调大（如 3–8 秒），先小范围试跑，勿并行多开。

真实 X 上 UserTweets / UserByScreenName 形状**未经本仓库实测**，失败时请看同步页错误提示，并尝试刷新书签页或「重新扫描」queryId。

## 6. 批量操作

在书签列表勾选条目后，工具栏可：

- 移动到文件夹（可新建）  
- 加 / 去标签；抓取线程（TweetDetail，同作者自回复链）  
- AI 归类（需先在设置配置 LLM）  
- **取消 X 端书签**（DeleteBookmark；默认二次确认；可选同时删本地）——**不可撤销**  
- 删除本地记录  

「推送到 X 的文件夹移动」为实验性选项，默认请谨慎开启。

## 7. 导出与分批导出

**列表页**可用导出面板（见 §3b）。「书签」卡片页仍可用导出菜单：对「已勾选；未选则当前搜索结果」：

- JSON / CSV（带 BOM）/ Markdown（单文件）  
- Obsidian：zip，每条一个带 frontmatter 的 `.md`  
- 打印友好页 → 浏览器「另存为 PDF」  
- 媒体批量下载（图片倾向 `:orig`，视频取较高码率 mp4）

**大数据量请用分批导出**（书签页导出菜单或设置）：

- 默认每批 **1000** 条（可在设置改，约 100–10000）。  
- 优先打成**一个总 zip**，内含多批文件名如 `bookmarks_001_of_059_00001-01000.json` 及 `.meta.json`。  
- 超过约 10 批会再拆成多个 zip。  
- 过程中会显示「正在导出第 x/y 批」。

设置页的「备份导出」会读全库，大库请耐心等待。

## 9. 设置页要点

| 项 | 说明 |
| --- | --- |
| 语言 | 中文 / English |
| 主题 | 深色（默认）/ 浅色；也可在列表工具栏一键切换 |
| 同步文件夹 | 是否拉 BookmarkFolders 相关接口 |
| 标记已删除/已取消 | 全量成功后的 tombstone / unbookmarked 逻辑 |
| 同步时抓线程 | 同步阶段可选抓取同作者线程 |
| 推文件夹到 X | 实验性 |
| 批量取消二次确认 | 建议保持开启 |
| 页间延迟 min/max | 越大越安全，发帖同步尤甚 |
| 每页条数 | 请求分页大小（有上下限） |
| 导出每批条数 | 分批导出切片大小 |
| LLM | endpoint（OpenAI 兼容）、Key、模型（常用模型下拉 +「自定义」自由输入）、批次与间隔；Key 仅存本机 `chrome.storage.local` |
| 备份导入导出 / 清空 | 清空会删本地 IndexedDB 数据，请先备份 |

配置 LLM 并保存时，扩展可能请求该 API 域名的**可选权限**。推文文本会发往你配置的接口；无 Key 时书签页不显示 AI 入口。

## 10. 升级与数据保留

1. 重新 `npm run build`，或解压新版发布包中的 `dist/`。  
2. `chrome://extensions` → 本扩展 → **重新加载**。  
3. 数据库名 `bookmark-keeper` 不变时，**IndexedDB 数据会保留**（schema 升级如 v3 的 `source` 索引会自动迁移；旧书签缺省视为 `bookmark`）。  
4. 除非你点了「清空本地数据」，一般**不必**重新全量同步。

## 11. 常见问题（简）

**同步立刻失败 / auth**  
再登录 x.com，打开 `/i/bookmarks` 刷新；检查扩展权限。

**queryId / 无法识别响应**  
同步页点「从 x.com 脚本重新扫描」；仍失败说明接口可能已变，需更新代码中的默认 queryId 或解析器。

**侧边栏以前卡死，现在呢？**  
大库改为索引分页 + 后台分批建搜索索引；首次关键字搜索在索引未完成前可能较慢。

**会不会上传我的数据？**  
书签与发帖数据默认只存本机。唯一例外是你主动配置的 LLM 归类（文本发往该 API），以及你自己导出/备份到本机文件。

更多风险条目见 README「已知风险」。
